# Checkout & Post-Checkout Implementation Roadmap (Gemini Analysis)

**Date:** December 1, 2025
**Context:** Analysis of Medusa backend and Fabric Store frontend.

## Executive Summary
The core B2C checkout flow (Stripe integration, address capture, order creation) is technically complete and functional. However, the platform currently lacks critical business logic specific to a fabric marketplace—most notably inventory reservation, minimum order quantity (MOQ) enforcement, and automated post-checkout fulfillment workflows.

## Recommended Next Steps (Prioritized)

### 1. Enforce Minimum Order Quantities (MOQ)
**Priority:** 🔴 Critical (Revenue Protection)
**Status:** Defined in seed data (`minimumOrder: '2'`) but ignored in checkout.
**Risk:** Users can place unprofitable orders (e.g., 0.5 yards) that cost more to process than the margin generated.
**Implementation Plan:**
- **Frontend (`frontend/experiences/fabric-store/app/cart/page.tsx`):**
    - Implement validation logic to check line item quantity against `minimumOrder`.
    - Block the "Proceed to Checkout" action if validation fails.
    - Display clear error messages to the user.
- **Backend:**
    - Implement a guard in `CartService` or a `cart.update` subscriber.
    - Reject payment session initialization if cart contains invalid items.

### 2. Implement Inventory Reservation Strategy
**Priority:** 🟠 High (Prevent Overselling)
**Status:** Inventory is only adjusted *after* order completion.
**Risk:** Race conditions during high-traffic periods (or limited stock drops) can lead to overselling.
**Implementation Plan:**
- **New Entity:** Create `InventoryReservation` (or leverage Medusa's Inventory Module reservations if fully enabled).
- **Workflow:**
    - Trigger reservation when a user enters the checkout flow or initializes a payment session.
    - Set a TTL (Time To Live) of 15-30 minutes.
    - Release reservation automatically via a background job if TTL expires without conversion.
    - Release reservation immediately on payment failure or session cancellation.

### 3. Create "Order Placed" Event Subscribers
**Priority:** 🟠 High (Operations Automation)
**Status:** No automation exists for `order.created`; relies on manual admin checks.
**Risk:** Operational bottlenecks and delayed fulfillment.
**Implementation Plan:**
- **New Subscriber:** `medusa/src/subscribers/order-placed.ts`
- **Logic:**
    1.  **Notifications:** Trigger `resend_notification` module to send the transactional order confirmation email.
    2.  **Fulfillment Record:** Automatically create a fulfillment object in "Pending" state for the warehouse team.
    3.  **Future:** Generate a "Cutting Ticket" (PDF or digital record) containing specific fabric cut instructions.

### 4. Volume Pricing Tiers (Wholesale Logic)
**Priority:** 🟡 Medium (Revenue Growth)
**Status:** Domain model supports wholesale, but cart logic uses simple unit pricing.
**Risk:** Missing revenue opportunities from bulk buyers (B2B).
**Implementation Plan:**
- **Backend:** Enable/Configure `@medusajs/pricing` module.
- **Data:** Define Price Lists for different quantity tiers (e.g., 10-50 yards, 50+ yards).
- **Frontend:**
    - Update `OrderSummary.tsx` to fetch tiered prices.
    - Display "Buy X more to save Y%" messaging in the cart.

### 5. Fulfillment & Shipping Integration
**Priority:** 🟡 Medium (Operational Efficiency)
**Status:** Manual fulfillment only.
**Risk:** High manual labor cost per order; lack of tracking updates for customers.
**Implementation Plan:**
- **Backend:** Integrate a Fulfillment Provider (e.g., Shippo, EasyPost, or a custom provider).
- **Workflow:**
    - Generate shipping labels upon fulfillment creation.
    - Sync tracking numbers back to the order.
    - Trigger "Order Shipped" email with tracking link.

## Conclusion
Immediate focus should be on **PR #1 (MOQ)** and **PR #3 (Order Subscribers)**. These require low effort but provide high value by validating orders and ensuring they are properly acknowledged.
